# 七、答案置信度 · 刨根问底协议（root-digging）

> 目标：确保输出的答案是「全网当前时间点下置信度最高的答案」。与 search-freshness.md 互补：时效协议管「答案过没过期」，刨根问底管「答案对不对、是不是全网最优」。双入口：模型对重要答案自动执行（全局规则见 SKILL.md），用户点名「刨根问底」时按第 7 节模板执行。
> v1.3.0 修订：渠道多样性新增「时间同源性检查」与「一手来源再分级」；🟢 置信门槛对价格/活动类收紧（须当日实测购买页）。修订源于 2026-08 Coding Plan 价格调研实战复盘。

---

## 1. 触发判定（先于一切搜索）

只对「重要问题」启动，命中任一信号即触发：

| 信号 | 判定 |
|---|---|
| 操作性结论 | 用户会照做的命令 / 配置 / 步骤（对应 L2+） |
| 数据引用 | 用户会转述、写进文档的数字与事实 |
| 决策依据 | 影响选型、购买、方案取舍的关键信息 |
| 用户点名 | 明说「刨根问底」「全网核实」「确认一下」「这个数据靠谱吗」 |
| 模型自评低置信 | 训练知识可能过期，或自身对答案不确定 |

**不触发**：闲聊、纯观点讨论、一句话可答的稳定概念（L0）——保留奥卡姆剃刀优先原则，避免每个问题都变慢变贵。

## 2. 渠道多样性硬规则

- **最低渠道数**：L2 两轮 → ≥2 个独立渠道；L3 多轮交叉 → ≥3 个独立渠道，且其中至少 1 个一手来源（官方文档 / 官网 / 原始论文 / 权威发布）。
- **独立性判定**：不同主办方、不同作者、无转载关系。同一篇文章被 CSDN / 公众号 / 博客园互相搬运 = 1 个渠道，不算多源。
- **时间同源性检查**（v1.3.0）：多个来源若结论一致，但日期集中于同一时段且互相措辞雷同（疑为同一份快照的扩散），无论表面有多少个来源，只能计 1 个有效渠道；必须引入更晚日期或当日实测的源打破同源，才恢复多源计数（详见 search-freshness 第 8 节 P3）。
- **一手来源再分级**（v1.3.0）：同为官方，实时购买页/控制台 > 官方公告（带日期）> 产品文档/帮助中心（更新滞后）；文档与实时页面冲突时以实时页面为准（P2）。
- **渠道类型池**（每次至少覆盖 2 种不同类型）：官方一手源、权威媒体、垂直社区（GitHub issues / Stack Overflow / 专业论坛）、数据站 / 百科、英文源。
- **中文特化联动**：命中转载农场 / 滞后信号，立即切英文重搜（复用 search-freshness 第 5 节）。

## 3. 五步流程

1. **定级**：按 search-freshness 的 L0~L3 定投入级别，敏感型先做 T0 分类；
2. **多渠道取证**：按渠道多样性规则取源，逐个记录 URL + 日期；
3. **交叉比对**：结论分「多源一致 / 部分冲突 / 互斥」三类；摘要不算证据，必须打开原文核对（R1）；
4. **冲突裁决**：官方 > 权威媒体 > 社区；时间新的 > 时间旧的；无法裁决时并列呈现，不硬选边；
5. **置信落款**：按第 4 节红绿灯输出，附来源数 + 核查日期。

## 4. 置信度红绿灯（真值轴，区别于时效轴）

| 灯 | 标准 | 输出要求 |
|---|---|---|
| 🟢 高置信 | ≥2 独立渠道一致（已排除时间同源性假阳性），且含 ≥1 个一手 / 权威源；价格/活动类还须满足 search-freshness P4 三查（截止日 + 当日实测在售 + 限制条款） | 结论 + 证据清单（每源标注日期） |
| 🟡 中置信 | 仅单一可靠源，或多源但全为二手，或多源一致但未打破时间同源性 | 结论 + 明示「单一来源/快照扩散，关键场景建议再验」 |
| 🔴 低置信 | 未能交叉确认 / 存在无法裁决的冲突 | 明说「暂未核实」+ 已排除的路径 + 求证出路 |

## 5. 模型主动追问规则

模型在为关键信息检索时，若自评当前最佳答案置信度不足（🟡/🔴 且影响结论）：
- 先补搜 1~2 轮（换渠道类型 / 切英文 / 直查官方）；
- 两轮后仍未提升 → 按失败兜底输出，禁止把低置信答案包装成确定结论。

## 6. 交付格式

输出三件套（红绿灯 + 结论 + 证据）：

- **红绿灯行**：🟢 已交叉验证（N 源一致，核查于 YYYY-MM）
- **结论行**：当前时间点置信度最高的答案
- **证据清单**：[来源1 · 日期] [来源2 · 日期] …
- **冲突说明**（如有）：分歧点 + 裁决依据
- **求证出路**（🔴 必带 / 🟡 可带）：下一步该查什么

## 7. Prompt 模板（用户主动点名时）

```
我想刨根问底的问题是：【填写问题】。请对答案做全网多渠道交叉验证：1. 至少 3 个彼此独立的渠道（其中至少 1 个一手来源），逐个给出来源与日期；2. 指出各渠道结论是否一致、冲突点在哪；3. 如有冲突，按「官方优先、新信息优先」裁决，无法裁决就并列呈现；4. 最终给出当前时间点下置信度最高的答案，并用红绿灯标注置信等级（绿=多源一致含一手源；黄=单一可靠源；红=未能交叉确认）；5. 附上「如果还要更确定，下一步该查什么」。
```
