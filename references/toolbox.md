# 思维工具库（toolbox）

> 21 件经典思维工具的四层定义与调用规则（18 件新定义 + 3 件原模板摘录指引）。★ = 用户核心 6 把。每件工具按「定义 -> 调用时机 -> 执行步骤 -> 典型反例」组织（原模板保留件为摘录指引）。来源：芒格多元思维模型 / Farnam Street、Heath 兄弟《决断力》（WRAP）、Mike Caulfield SIFT、贝叶斯方法、丰田 5 Whys、麦肯锡 MECE、Gary Klein 预验尸、Bezos 可逆性测试。

# 第一层：理解问题层（问对问题）

## §1 第一性原理 ★

**定义**：把问题剥到不可再拆的基本事实，从零开始重推，拒绝用类比和惯例作论据（「大家都这么做」不是理由）。

**调用时机**：方案反复打补丁仍不好用；答案停留在「行业惯例」「别人都这么做」；要设计全新东西而非复制模板。

**执行步骤**：
1. 列出已经确认、无法绕开的基本事实
2. 单独列出「习惯性接受却从未验证过的假设」
3. 写清真正想实现的目标与现实约束
4. 暂时放下行业惯例，只从基本事实 + 目标 + 约束重推路径
5. 输出：原方案中只在修补表面的部分 / 从事实重推的新路径 / 成立前提 / 验证第一步

**典型反例**：把「我们公司一直是这么做的」当成基本事实--它是假设不是事实，第一性原理正是要挑战它。

## §2 奥卡姆剃刀 ★ / 汉隆剃刀

**定义**（奥卡姆）：如无必要，勿增实体--多个解释都能覆盖事实时，选最简单的。**定义**（汉隆）：能用愚蠢/疏忽解释的，不要归咎于恶意。

**调用时机**（奥卡姆）：检索启动前先剃--最简单解释优先，防止过度工程；诊断任务分级时的 🟢 直答依据。**调用时机**（汉隆）：解读他人行为、动机类问题时先假设无心之失。

**执行步骤**：
1. 列出所有候选解释
2. 数每个解释需要的额外假设数量
3. 需要假设最少的优先；仅当简单解释覆盖不了关键事实时才升级复杂解释

**典型反例**（奥卡姆）：把三个巧合叠加的阴谋论当成最简解释--真最简解释往往是「出了个错」。

## §3 二阶思维 ★

**定义**：一阶思维问「做 X 会得到 Y」；二阶思维追问「得到 Y 之后，又会引发什么？」

**调用时机**：方案「好得不像话」时；决策有连锁反应、涉及他人反应（博弈）时；短期收益 vs 长期代价权衡时。

**执行步骤**：
1. 写下一阶后果（直接的、明显的）
2. 对每个一阶后果追问「然后呢？」至少两层
3. 特别追问：其他人/系统会如何反应？6 个月后呢？
4. 输出：直接收益 / 二阶代价 / 谁会在二阶层受损并反弹 / 时间拉长后结论是否反转

**典型反例**：促销拉新（一阶：用户涨了；二阶：折扣锚定，正价再也卖不动）。

## §4 5 Whys

**定义**：对现象连问「为什么」直到根因，区分「治标的症状」与「治本的病因」。

**调用时机**：现象与根因可能错位（系统总在同一处出问题）；用户描述的是表象时。

**执行步骤**：
1. 精确陈述现象（不掺解释）
2. 连问为什么，每层答案必须是可验证的事实而非猜测
3. 问到「再问为什么只会得到人的动机/物理定律」时停（通常 3～5 层）
4. 输出：根因链 + 对应根因而不是症状的对策

**典型反例**：链条中某一环跳到「人不行」这种不可行动的答案--根因必须还能动手改。

## §5 MECE

**定义**：Mutually Exclusive, Collectively Exhaustive--分解维度相互独立、合并起来穷尽全部。

**调用时机**：分解任何复杂问题/任务/清单前先建骨架；分类讨论、框架搭建。

**执行步骤**：
1. 选定分解轴（按流程/按对象/按原因，一次只用一轴）
2. 检查互斥：类目间有无重叠
3. 检查穷尽：合并是否覆盖全部，留「其他」兜底前先穷举已知
4. 输出：分层结构图，每层标注该层的分解轴

**典型反例**：一次混用两把尺子（既按渠道又按地区切同一层）导致类目重叠。

## §6 假设澄清

**定义**：显式列出结论依赖的全部隐含前提，逐一挑战其真实性。

**调用时机**：跨入陌生领域（域内常识可能是域外谬误）；结论链条长且依赖未验证前提；两个方案争执不下时（先查是否前提不同）。

**执行步骤**：
1. 从结论反推：要它成立，必须先成立什么？逐条列出
2. 每条前提标注：已验证 / 待验证 / 大概率为假
3. 攻击最脆弱的前提：如果它为假，结论怎么变？
4. 输出：前提清单 + 最脆弱前提 + 它被证伪时的备选结论

**典型反例**：把「过去一直成立」当作「将来也会成立」（隐含平稳性假设）。

## §7 后向推理

**定义**：从终态（目标已达成）倒推每一步必经节点，而非从现状正向摸索。

**调用时机**：有明确目标但不知从哪开始；正向路径太多容易迷路；里程碑规划。

**执行步骤**：
1. 写清终态的完成标准（可判定，非「做好」）
2. 问「紧挨着终态之前，必须已经完成什么？」逐层倒推
3. 标出倒推链上的关键依赖与并行支线
4. 输出：倒推出的关键里程碑序列 + 第一个可执行动作

**典型反例**：终态定义模糊（「做成自媒体」）导致倒推链发散--先钉死可判定的终态。

# 第二层：检索质量层（答案更准）

> 本层另有三件工程化协议（时效核查、价格 P1-P4、刨根问底）不在本文件，见 `search-freshness.md` 与 `root-digging.md`，v1.3.0 规则整体继承，执行时以那两个文件为准。

## §8 SIFT 横向阅读

**定义**：Mike Caulfield 的专业事实核查四步法：Stop（停）/ Investigate（查源）/ Find better coverage（找更优报道）/ Trace（追原始语境）。核心是横向阅读--不留在页面内自证，而是跳出去看别的可信源怎么说这个源。

**调用时机**：检索中遇到陌生信源需要快速定级；引用前判断来源可信度；中文内容农场嫌疑时。

**执行步骤**：
1. **Stop**：这源我认识吗？不认识且重要 -> 继续往下
2. **Investigate**：搜「来源名 + 是什么/信誉」，看第三方怎么评价它（Wikipedia / 事实核查站）
3. **Find better coverage**：搜该话题，找权威媒体 / 官方 / 学术源的同题报道对比
4. **Trace**：把引用的数字/引语追回原始出处，确认没被断章取义

**典型反例**：在页面内部找「关于我们」自证可信--自述无意义，要跳出页面横向验证。

## §9 贝叶斯更新

**定义**：置信度不是非黑即白，而是概率；每条新证据按「先验 × 证据强度 = 后验」持续更新判断，而非一次性定死。

**调用时机**：多渠道证据陆续汇入需动态汇总；证据互相矛盾需裁决权重；跟踪事件进展修正判断。

**执行步骤**：
1. 先写下先验（基于已知信息的初始置信度，如 50%）
2. 每条新证据问：如果假设为真，看到它的概率多大？为假呢？（似然比）
3. 按证据强度更新置信度：强证据大幅移动，弱证据小幅移动，同源重复证据只算一次（防快照扩散假阳性，联动 root-digging P3）
4. 输出：当前置信度 + 最近一次改变它的证据 + 什么证据会让它反转

**典型反例**：把十条转载同一篇快照的文章当成十条独立证据--同源只算一次，这是 v1.3.0 P3 规则的贝叶斯表述。

## §10 横纵分析法（原模板保留，要点摘录）

**定义**：纵轴看研究对象的历史演化（怎么走到今天），横轴看它与竞品的当下定位差异，两轴交叉出洞察。

**调用时机**：深度系统研究陌生产品/公司/人物/技术/行业。须联网，全程执行 search-freshness 协议，报告 8000～15000 字分章交付。完整模板见 `learning.md`。

## §11 事实核查（原模板保留，要点摘录）

**定义**：把待核说法拆成「可验证事实 / 推导结论 / 价值判断」三部分，事实部分联网核来源、样本、时间、上下文，标记五级（已证实 / 基本成立需收窄 / 存在争议 / 证据不足 / 明显错误）。涉操作方法时同步走 search-freshness。完整模板见 `learning.md`。

# 第三层：回答质量层（切中要害）

## §12 双层解释法（点名保留，原模板摘录）

**定义**：费曼层（生活化语言 + 具体例子）+ 专业层（准确术语 + 核心机制 + 适用边界 + 常见误解），最后附小白/专业术语对照表、易错点、3 道理解自测题。

**调用时机**：用户说「这个概念我完全听不懂」。完整模板见 `learning.md`。

## §13 多专家会诊（点名保留，原模板摘录）

**定义**：选 3 种真正互补的专业视角，各自回答「怎么重定义问题 / 推荐路径 / 别人忽略的风险 / 什么证据会改变判断」，再互质疑，输出综合方案 + 适用条件 + 最大风险 + 退出条件 + 第一步行动。信息不足时先只问一个最关键问题。

**调用时机**：复杂问题单一视角不够，需要互补视角互相挑战。完整模板见 `problem-solving.md`。

## §14 反向拆解（原模板摘录）

**定义**：对优秀范例先一句话说清它解决什么问题，再拆「服务谁 / 什么结构 / 哪些关键选择拉开差距 / 完成标准」，输出可复用规律 + 操作清单 + 小练习。完整模板见 `learning.md`。

## §15 跨领域借解（原模板摘录）

**定义**：剥掉行业术语抽象出问题底层结构，从 ≥3 个远距离领域找相似案例，翻译回当前处境，推荐低成本可逆实验。完整模板见 `problem-solving.md`。

# 第四层：决策质量层（建议不平庸）

## §16 逆向思维 ★

**定义**：芒格：「反过来想，总是反过来想」。不问「怎么成功」，先问「怎么必然失败」，把失败路径列全后逐一规避。

**调用时机**：计划制定后、行动前压测；成功路径想不清但失败路径好列举时；重大决策。

**执行步骤**：
1. 假设这件事一年后彻底失败了
2. 倒推：最可能导致失败的原因按概率排序（列 5～8 条）
3. 对每条问：现在的计划里有没有防线？没有就补
4. 输出：失败模式清单 + 对应防线 + 现有计划的最大死穴

**典型反例**：只列「竞争激烈」「市场不好」这类外部归因--优先找自己可控的失败路径。

## §17 机会成本 ★

**定义**：任何选择的真成本不是账面支出，而是被放弃的最优替代选项的价值。

**调用时机**：任何「要不要做」类决策；资源分配；「看起来免费」的东西。

**执行步骤**：
1. 问：做 A 的话，同一时间/钱/注意力最值得做的 B 是什么？
2. 给 B 估值（不用精确，量级即可）
3. 决策标准从「A 有没有收益」改为「A 的收益是否跑赢 B」
4. 输出：被放弃的最优替代 + 量级估算 + 该决策的真实成本

**典型反例**：只算 A 的直接收益（「又不花钱，试试呗」）而忽略时间/注意力的去向--免费的最贵。

## §18 安全边际 ★

**定义**：给「你不知道自己不知道」的部分留缓冲。系统满负荷运行 = 零韧性；计划排满 = 无容错。

**调用时机**：估算工期/成本/容量时；做不可逆承诺前；系统上线前；任何依赖预测的决策。

**执行步骤**：
1. 问：这个估算/计划依赖哪些假设成立？
2. 每个假设失败时代价多大？可逆吗？
3. 对不可逆且高代价的部分加缓冲（典型做法：时间 ×1.5、预算 ×1.3、容量留余）
4. 输出：安全边际清单 + 哪些地方刻意留了冗余 + 为什么

**典型反例**：按最好情况做计划（每件事都「顺利的话两天」）--串联任务里一处延误全线崩。

## §19 可逆性测试

**定义**：Bezos 双向门框架。双向门（可逆）决策应快速试错，单向门（不可逆）决策才值得慢与贵。决策流程与可逆性错配是最大的浪费。

**调用时机**：可逆性存疑时先测门；决定「该花多大力气决策」本身时。

**执行步骤**：
1. 问：如果这个决定错了，我能退回来吗？代价多大？
2. 双向门 -> 快速决定 + 试错纠偏；单向门 -> 慢流程（WRAP + 预验尸）
3. 注意伪装：有些门看着双向实际单向（公开承诺、信任损耗）
4. 输出：门的属性判定 + 匹配的决策速度

**典型反例**：用单向门的郑重其事纠结午饭吃什么；用双向门的速度签竞业协议。

## §20 WRAP

**定义**：Heath 兄弟《决断力》四步，对治四大决策恶棍：W（Widen 拓宽选项，治窄框架）→ R（Reality-test 现实检验，治确认偏误）→ A（Attain distance 拉开距离，治短期情绪）→ P（Prepare to be wrong 准备犯错，治过度自信）。

**调用时机**：重大情绪化决策；问题被框成「做还是不做」二选一时；几个选项「都对」难分高下时。

**执行步骤**：
1. **W**：拒绝「是否」句式，强制生成第三选项；问「如果现有选项全消失，我会做什么」
2. **R**：主动找反面证据；问「什么必须为真这个选项才成立」；能小实验就先小实验
3. **A**：10/10/10（10 分钟/10 个月/10 年后怎么看）；问「朋友来问，我会给什么建议」
4. **P**：设绊网（什么信号出现就重新决策）+ 为失败预演应对
5. 输出：完整选项集（≥3）+ 每项的致命假设 + 情绪剥离后的判断 + 绊网清单

**典型反例**：把决策框成「要不要分手 / 要不要辞职」的二元窄框架--W 步正是要破它。

## §21 预验尸（pre-mortem）

**定义**：Gary Klein 方法。假设「项目已经彻底失败」，团队围坐写下失败原因--把事前不可言说的风险变成事前可讨论的清单。与 §16 逆向思维同源，但预验尸发生在方案定稿前的最后一道闸。

**调用时机**：行动方案定稿前；多人项目启动前；高风险承诺前。

**执行步骤**：
1. 想象未来某时点，这个决定/项目已确认彻底失败
2. 各自独立写「失败史」（独立写再汇总，防锚定）
3. 按概率 × 伤害排序失败原因
4. 对 top 3 逐条问：现在改动方案还来得及吗？
5. 输出：失败史清单 + 方案修改项 + 无法防御但需监控的早期信号

**典型反例**：预验尸变成集体焦虑大会--只输出「竞争、资金、运气」这类不可行动项等于没做。

- **防错双保险**：时效核查（防过期）+ 刨根问底（防错误），规则见两个协议文件
